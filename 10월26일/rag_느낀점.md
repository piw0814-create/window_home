1. 표 처리하고 출처 연결에서 많은 찐빠가 났다
2. 그래서 근거 검수를 쎄게하면 제대로 된 답변 통과가 안되고, 약하게 해버리면 또 이상한걸로 하고
3. 각종 먼가 사투리? 같은 의미의 다양한 표현? 제대로 안되던것 같다
4. 그 연장선으로 먼가 단위도 너무 엄격하게 검증해버리면 너무 통과 안시키고...

- 프로젝트에서 어려웠던 점은 **답변을 그럴듯하게 만드는 것보다, 실제 업무 질문에 맞는 근거를 찾아 정확히 연결하고 안정적으로 제공하는 것**

| 어려웠던 점                         | 실제로 겪은 문제                                                                                                         | 대응·배운 점                                                                                                |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| **① PDF 표의 의미 보존**            | 텍스트를 추출해도 행·열·단위·각주가 흐트러져 어떤 금액이 어떤 항목인지 불분명했음                                        | 검수한 구조화 표를 활용. **임베딩 모델보다 원본 추출 품질을 먼저 확인해야 함**                              |
| **② 답변과 출처 연결**              | 관련 문서를 찾았어도 다른 표나 페이지를 인용하거나, 수치와 출처 연결이 어긋났음                                          | 문서·판본·페이지·청크·표 항목을 함께 관리. **검색 성공과 정확한 인용은 별개**였음                           |
| **③ 검수 강도 조절**                | 검수를 강하게 하면 정상 답변도 보류되고, 약하게 하면 대상·조건이 다른 설명이 통과할 수 있었음                            | 형식 오류와 사실·의미 오류를 구분해야 함. 전체 답변을 일괄 폐기하는 방식에도 한계가 있었음                  |
| **④ 다양한 사용자 표현 이해**       | 띄어쓰기·오타·구어체·같은 뜻의 표현에 따라 레시피 조회가 상담으로 빠지거나 불필요한 확인 질문을 했음                     | 입력 표현을 공통 의미로 정규화. 표현마다 예외를 추가하기보다 **공통 분기 기준을 만드는 것**이 중요했음      |
| **⑤ 수치·단위 검증**                | 표기만 다른 값을 틀렸다고 판단하거나, 단위 인식 오류로 정상 답변을 차단했음. 실제로 `10곳`과 `10가지` 비교 오류가 있었음 | 표기 정규화·확실한 환산은 코드로 처리하되 대상과 조건은 유지. **문자 일치만으로 사실성을 판단할 수 없었음** |
| **⑥ 질문 의도·주체 구분**           | 예비 점주가 볼 자료를 물었는데 가맹본부의 정보공개서 등록 서류를 설명하는 등 방향이 어긋났음                             | 문서 탐색과 내용 상담을 구분. **틀린 대상을 검색한 문제는 마지막 검수만으로 해결하기 어려웠음**             |
| **⑦ 비슷한 근거 중 적절한 것 선택** | 신규 가맹 교육비와 운영 중 교육훈련비처럼 용어는 같지만 적용 상황이 다른 자료가 함께 검색됐음                            | 하이브리드 검색·재순위화·주변 문맥 조회를 적용. 단어 유사도뿐 아니라 대상·시점·예외를 봐야 했음             |
| **⑧ 복합 질문 처리**                | “별도인가요? 납부 기한도 같은가요?”에 한 항목만 답하거나, 일부 근거 부족 때문에 전체가 보류됐음                          | 질문을 독립적인 요구사항으로 나누고, 확인된 부분과 부족한 부분을 구분할 필요가 있었음                       |
| **⑨ 대화 맥락 연결**                | “그건 언제까지?”, “교육비도 포함이야?”, “아이스” 같은 후속 입력을 앞선 대상에 연결해야 했음                              | 필요한 경우만 대화 맥락을 활용. **이전 AI 답변을 사실 근거로 재사용하지 않는 것**도 중요했음                |
| **⑩ 근거 없는 질문 대응**           | 문서에 없는 내용도 상식으로 답하거나, 반대로 범위 밖 질문을 서버 오류로 처리했음                                         | 근거 부족·추가 조건 필요·시스템 장애를 구분. 모르는 이유를 사용자에게 명확히 전달해야 했음                  |
| **⑪ 법령의 조건·참조 관계**         | 같은 조항 안의 다른 대상이나 예외가 섞이고, 다른 조항·시행령까지 참조하는 질문은 판단이 까다로웠음                       | 관련 문맥을 추가 조회했지만, **복잡한 다단계 법령 참조는 후속 과제**로 남겼음                               |
| **⑫ 판본·적용일·권한 관리**         | 새 자료가 등록됐다는 이유만으로 바로 검색하면 안 됐고, 사용자에게 허용된 배포 판본을 선택해야 했음                       | 승인·색인·배포·적용 시점을 구분하고 Java와 RAG 양쪽에서 검색 범위를 확인                                    |
| **⑬ 응답 속도·API 사용량**          | 재순위화·생성·검수·재작성마다 LLM을 호출하고 긴 근거를 반복 전달해 지연과 사용량이 늘었음                                | 레시피는 코드 조회로 분리하고 호출·보완 상한 설정. 재순위화의 효과 대비 비용은 추가 비교가 필요             |
| **⑭ 서비스 간 환경설정 일치**       | Java와 RAG의 JWT 키가 달라 정상 로그인 후에도 `UPSTREAM_ERROR`가 발생했음                                                | 컨테이너에 실제 적용된 설정을 비교해야 했음. **검색 문제와 인증·연결 문제를 먼저 분리**하는 것이 중요       |
| **⑮ 수정 영향과 평가**              | 한 질문을 고친 변경이 다른 질문의 분기·검수에 영향을 줄 수 있었고, 같은 질문도 모델 결과가 달라졌음                      | 정상·복합·근거 부족·후속 질문을 함께 확인. **한 번 성공한 결과를 전체 안정성으로 해석하면 안 됨**           |
| **⑯ 구현 복잡도 관리**              | 실패 사례마다 프롬프트·예외 조건을 추가하면 구조를 이해하고 유지하기 어려워졌음                                          | 공통 정규화·조회·검증 로직으로 통합하고, 확실한 처리는 코드에 맡기는 방향으로 정리                          |

- 요약

1. **데이터:** PDF를 읽는 것과 표의 의미를 정확히 보존하는 것은 달랐다.
2. **검색·이해:** 관련 문서를 찾는 것과 질문의 대상·조건에 맞는 근거를 찾는 것은 달랐다.
3. **신뢰성:** 오답을 막으면서 정상 답변을 과도하게 차단하지 않는 검수 설계가 어려웠다.
4. **운영:** 정확도·응답 시간·API 비용·구조의 단순함을 함께 고려해야 했다.

- 회고 문장으로 정리하면:

> **RAG의 핵심 난점은 답변 생성 자체보다 데이터 구조 보존, 사용자 의도 해석, 근거와 주장 연결, 그리고 과도한 보류 없이 오류를 막는 검수 설계에 있었다. 이를 해결하면서 AI가 의미를 판단할 영역과 코드가 확실하게 처리할 영역을 구분하는 것이 중요하다는 점을 배웠다.**
