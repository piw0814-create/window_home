## 궁금한 점

왜 컨테이너 썻나?????

    핵심은 “내 컴퓨터가 아닌 곳에서도 똑같이 실행하기 위해서”
    예를 들어 네 프로젝트를 친구에게 그냥 보내면 친구는:

    Java 몇 버전?
    환경변수 뭐 넣어야 함?
    어떻게 빌드함?
    어떻게 실행함?
    포트 몇 번?

    을 맞춰야 해.

    Docker로 만들면:

    Docker 이미지
    =
    내 앱
    + Java 실행환경
    + 실행 방법

    을 묶어놓을 수 있어

    그러면 다른 서버에서도:

    docker run ...으로 거의 같은 환경에서 실행할 수 있는 거야.

Docker는 만들어진 서버를 포장해서 실행·배포하기 쉽게 만드는 기술
Spring Boot가 서비스를 만들고, Docker는 그 서비스를 어디서든 일정한 환경으로 실행할 수 있게 포장

대표적으로는 이런 차이 때문에 “내 컴퓨터에선 되는데 다른 컴퓨터에선 안 됨”이 생겨.

    Java 버전 차이: 나는 Java 21인데 친구는 Java 17이면 실행 자체가 실패할 수 있음.
    DB 주소/포트 차이: 내 환경은 localhost:3379/sql_db인데 친구는 MariaDB가 없거나 포트가 다를 수 있음.
    환경변수 차이: JWT_SECRET, DB 비밀번호, API Key 등이 내 컴퓨터에만 설정돼 있으면 친구 컴퓨터에서는 실행 실패.
    OS 차이: macOS와 Linux/Windows는 파일 경로, 권한, 쉘 명령 등이 다름.
    설치된 프로그램 차이: 나는 MariaDB, Java, 필요한 도구가 설치돼 있는데 친구는 없을 수 있음.
    포트 충돌: 나는 9090이 비어 있는데 친구 컴퓨터에서는 이미 다른 프로그램이 사용 중일 수 있음.
    파일/권한 차이: gradlew 실행 권한이나 특정 폴더 경로가 다를 수 있음.

Docker는 이 중에서 특히 애플리케이션 실행 환경을 이미지 안에 고정하는 역할, 그래서 친구 컴퓨터가 Mac이든 Windows든 Linux든 Docker만 정상적으로 있으면 같은 이미지 환경으로 앱을 실행할 수 있어.
단, Docker가 모든 걸 자동 해결하는 건 아니야. 지금 네 구조처럼 MariaDB를 Docker 밖에서 돌린다면:

    Spring Boot Container
            ↓
    host.docker.internal:3379
            ↓
    내 컴퓨터의 MariaDB

DB 자체는 여전히 따로 준비되어 있어야 해.

그래서 더 완전히 맞추려면 나중에는:

    Docker Compose

    Spring Boot Container
            ↓
    MariaDB Container

처럼 Spring Boot와 DB까지 같이 컨테이너화하는 거야.

그러면 친구가 배포를 하더라도 데이터베이스는 내껄로 접근을 하게하는 그런걸로 만들수도 있나?

    가능해. 구조적으로는 친구가 자기 컴퓨터/서버에 Spring Boot를 배포해도, DB 연결 주소만 네 DB 서버를 가리키게 하면 돼.

    예를 들면:

    친구가 배포한 Spring Boot
            │
            │ JDBC
            ↓
    인터넷 / 네트워크
            ↓
    네 컴퓨터의 MariaDB
            ↓
        sql_db

    그러면 친구가 실행한 서비스에서 회원가입하거나 글을 쓰더라도 데이터는 전부 네 MariaDB에 저장돼.

    다만 지금 네 설정인:

    DB_URL=jdbc:mariadb://host.docker.internal:3379/sql_db

    은 안 돼. host.docker.internal은 컨테이너를 실행하고 있는 그 컴퓨터를 의미하니까, 친구가 실행하면 친구 컴퓨터를 가리켜.

    친구 서버에서 네 DB를 쓰려면 대략:

    DB_URL=jdbc:mariadb://네_DB_주소:3379/sql_db
    DB_USER=...
    DB_PASSWORD=...

    처럼 해야 해.

    문제는 네 개인 Mac의 MariaDB를 인터넷에 직접 노출하는 건 권장하지 않는다는 점이야. 하려면 MariaDB의 외부 접속 허용, 사용자 원격접속 권한, 방화벽/공유기 포트포워딩, 고정 IP 또는 DDNS 등이 필요하고, DB 포트를 인터넷에 그대로 여는 건 공격 대상이 되기 쉬워.

    실제로 배포할 때는 보통 이렇게 해.

                하나의 중앙 DB
                    ↑
            ┌───────┴───────┐
            │               │
        네가 배포한 서버    친구가 배포한 서버
        Spring Boot         Spring Boot

    중앙 DB를 AWS RDS, Azure Database, Cloud SQL 같은 관리형 DB 또는 별도의 DB 서버에 두는 식이야. 그러면 어느 Spring 서버가 실행되든:

    DB_URL=jdbc:mariadb://공용-db주소:3306/sql_db

    만 사용하면 모두 같은 회원·게시글·댓글·좋아요 데이터를 공유할 수 있어.

따라서 오늘은 “Spring Boot 애플리케이션을 Docker 이미지로 빌드하고 컨테이너로 실행하는 방법까지 구현했다. 다만 DB와 파일 저장소가 로컬 환경에 의존하므로 실제 외부 배포를 위해서는 데이터 저장소 분리와 운영 설정이 추가로 필요하다.”
