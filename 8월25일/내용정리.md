- llm 핵심 규모 요소
  - 사전 학습 코퍼스 규모

  - 연산규모
- 창발적 능력 : 특정 파라미터스케일에 도달하면 파인튜닝을 하지 않아도 능력이 비약적으로 상성하는 현상
- bag of word(문장 분리->단어 추출->어휘사전구축->빈도벡터) : 스파스 벡터 문제

  - CBOW

  - BPE Tokenizer : 사전에 없는 부단어 혹은 개별 문자로 나눔으로써 unk토큰이 불필요

# 궁금했던점

- 그럼 쿼리키밸류로 나누는 이유가 멀까 그냥 단순히 w하나만 두고 내적곱해서 유사도 하는거랑 실제로 어떤 차이가 있는지 관련 실험이 있어?

**“Q/K/V 세 개가 정말 필요한가? 그냥 `W` 하나로 임베딩을 변환한 뒤 서로 내적하면 안 되나?”**는 실제로 연구된 주제고, 결론부터 말하면:

> **가능하다. 실제로 꽤 잘 된다.**
> 다만 Q/K/V를 분리하면 특히 **방향성 있는 관계와 ‘검색 vs 전달’ 역할을 더 자유롭게 학습**할 수 있어서 표준 Transformer는 세 개를 쓴다.

오늘 자료는 표준 구조인 `Q=XW_Q`, `K=XW_K`, `V=XW_V`를 설명하고 있고, 아래 실험 얘기는 자료 밖의 연구 결과야.

### 1. 네가 말한 `W 하나` 방식부터 보면

각 토큰 `x`를 하나의 행렬로 변환해서:

```text
zᵢ = xᵢ W
zⱼ = xⱼ W
```

둘의 유사도를

```text
score(i,j) = zᵢ · zⱼ
```

로 구하면 돼.

충분히 Attention 비슷한 걸 만들 수 있어.

그런데 중요한 특성이 생겨.

```text
zᵢ · zⱼ = zⱼ · zᵢ
```

즉,

```text
score(i → j) = score(j → i)
```

가 돼.

**관계가 대칭적**이 되는 거야.

---

### 2. Q와 K를 따로 두면 이게 달라짐

표준 Attention은:

```text
qᵢ = xᵢ WQ
kⱼ = xⱼ WK

score(i → j) = qᵢ · kⱼ
```

반대 방향은:

```text
score(j → i) = qⱼ · kᵢ
```

이고 `WQ ≠ WK`니까

```text
score(i → j) ≠ score(j → i)
```

여도 아무 문제가 없어.

이게 생각보다 중요해.

예를 들어:

```text
The cat drank milk because it was thirsty.
```

`it` 입장에서:

```text
it → cat
```

을 강하게 찾아야 할 수 있어.

그렇다고 반대로

```text
cat → it
```

도 정확히 같은 관계 강도를 가져야 할 이유는 없잖아.

자연어에는 이런 방향성이 엄청 많아.

```text
대명사 → 선행사
동사 → 주어
동사 → 목적어
수식어 → 피수식어
현재 토큰 → 과거의 관련 토큰
```

그래서 Q/K 분리는 단순히 **유사도를 계산**하는 것보다,

> **A가 찾는 특성과 B가 검색될 특성을 서로 다르게 만들 수 있게 한다**

는 게 훨씬 정확한 설명이야.

수학적으로도 차이가 뚜렷해.

하나의 W면:

```text
score(i,j)
= xᵢ W Wᵀ xⱼᵀ
```

인데 `WWᵀ`는 대칭 행렬이야.

Q/K가 다르면:

```text
score(i,j)
= xᵢ WQ WKᵀ xⱼᵀ
```

이고

```text
WQ WKᵀ
```

는 일반적으로 대칭일 필요가 없어.

즉 **모델이 학습할 수 있는 관계의 범위 자체가 넓어진다.**

---

### 3. 그러면 V는 왜 또 따로 있냐

여기서 또 한 번 역할을 분리하는 거야.

```text
Q, K
↓
"누구를 가져올까?"

V
↓
"그 토큰에서 무엇을 가져올까?"
```

예를 들어 `"cat"`을 Attention 대상으로 선택했다고 해보자.

`K(cat)`은

```text
"나는 이런 상황에서 선택될 만한 토큰이다"
```

를 잘 표현하면 되고,

`V(cat)`은

```text
"선택됐을 때 다른 토큰에게 전달할 정보"
```

를 잘 표현하면 돼.

하나의 `W`를 쓰면 같은 벡터가:

```text
① 검색되기 좋아야 하고
② 다른 토큰과 비교하기 좋아야 하고
③ 실제 전달할 정보도 잘 표현해야 함
```

세 가지 일을 다 해야 해.

Q/K/V를 나누면:

```text
WQ → 찾는 데 최적화
WK → 검색되는 데 최적화
WV → 전달하는 데 최적화
```

로 각각 학습할 수 있어.

---

## 그런데 실제 실험을 해보니 재미있는 결과가 나옴

네가 의심한 것처럼 **Q/K/V 3개가 절대적으로 필수는 아니야.**

2025년 NAACL 논문에서는 아예

```text
Q = K = V
```

즉 **하나의 weight matrix를 세 역할에 공유**하는 BERT를 실험했어.

결과는 Attention 블록의 파라미터를 **66.53% 줄이면서도**, 작은 GLUE 태스크들에서는 표준 BERT와 경쟁력 있는 성능을 냈고 일부 조건에서는 더 좋은 결과도 보고했어. ([ACL Anthology][1])

즉:

> "W 하나 쓰면 Transformer가 망한다."

는 건 틀린 말이야.

---

더 흥미로운 실험도 있어. 2024년 연구에서는 **Q와 K를 얼마나 공유할 수 있는지** 실험했는데, 완전히 `Q=K`로 만들면 Attention이 지나치게 대칭적이 되면서 **방향 관계 표현이 단순해지고 pretraining loss가 악화**되는 현상을 보고했어. 반면 일부만 공유하면 상당히 많은 파라미터를 공유하면서 성능을 유지할 수 있었어. ([Proceedings of Machine Learning Research][2])

그리고 2026년 QKV projection을 체계적으로 비교한 연구에서는:

```text
① Q, K, V 모두 별도        ← 표준
② Q 별도, K=V 공유
③ Q=K 공유, V 별도
④ Q=K=V 모두 공유
```

를 비교했어.

특히 언어 모델에서는

```text
Q는 별도
K = V 공유
```

가 상당히 잘 버텼어. 300M/1.2B 규모 언어모델 실험에서 KV cache를 **50% 줄이면서 perplexity 악화가 약 3.1%** 수준이었다고 보고했어. 반대로 `Q=K`처럼 Query와 Key를 묶는 쪽은 **방향성을 잃는 문제가 더 중요**하게 나타났어. ([arXiv][3])

이 결과가 상당히 의미 있어.

```text
Q ↔ K 분리
→ 꽤 중요함
→ "찾는 쪽"과 "찾히는 쪽"의 방향성

K ↔ V 분리
→ 생각보다 덜 중요할 수도 있음
→ 실제로 공유해서 메모리를 줄이는 연구 존재
```

라는 거니까.

심지어 2021년 **Synthesizer** 연구에서는 아예 `Q·K` 기반 token-to-token 유사도 계산을 없애버린 Attention도 실험했는데 상당수 과제에서 Transformer와 경쟁력 있는 성능을 보였어. 즉 `QK dot-product` 자체도 유일한 정답은 아니라는 결과야. ([Proceedings of Machine Learning Research][4])

---

그래서 지금 수업 수준에서 가장 정확하게 정리하면 이거야.

```text
             하나의 W
                │
        같은 공간에서 비교
                │
       구현 단순 / 파라미터 ↓
                │
      하지만 역할이 서로 묶임
       관계도 기본적으로 대칭
```

반면:

```text
                입력 x
          ┌──────┼──────┐
          ↓      ↓      ↓
         WQ     WK     WV
          ↓      ↓      ↓
       Query    Key   Value
          └──┬───┘      │
             ↓          │
       누구를 볼까?     │
             ↓          │
       Attention Weight │
             └────×─────┘
                  ↓
           무엇을 가져올까?
```

즉 **QKV는 Attention이 작동하기 위한 절대적인 수학적 필수조건이라기보다, 모델에게 역할 분리와 더 큰 표현 자유도를 주는 설계**라고 보는 게 제일 좋아.

그리고 최근 연구들을 보면 네 질문처럼 **“사실 세 개까지 필요 없지 않나?”라는 의문이 실제 Transformer 경량화 연구의 한 방향**이 되고 있어. 특히 Q/K 분리의 방향성은 꽤 가치가 있지만, K/V는 경우에 따라 공유할 여지가 있다는 게 재미있는 부분이야.
