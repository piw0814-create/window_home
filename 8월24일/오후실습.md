- 필요한 Context를 어떻게 찾고, 선택하고, 연결하고, 유지할 것인가
  ① 무엇을 Context로 주어야 제대로 쓰나?
  ② 여러 근거를 어떤 순서로 연결해 계산하나?
  ③ 한 번의 추론을 어떻게 교차검증하나?
  ④ 필요한 Context를 다음 단계에서 어떻게 찾아가나?
  ⑤ Context가 길어졌을 때 무엇을 남기고 압축하나?

- 1. 프롬프트 5요소 설계 (Role, Objective, Context, Constraints, Format)
  - 브랜드 보이스 가이드 읽기
  - 고객사 L CRM 읽기
  - 신입 직원 이메일 초안 읽기
  - 어떤 규칙을 어겼는지 추출
  - 프롬프트 5요소 구성
  - AI검토 + 재작성 요청
  - 원문 규칙과 최종 이메일 재검수

            [Role]
            너는 A사의 세일즈/CS 이메일 품질 검수자다.

            [Objective]
            신입 직원이 작성한 이탈방지 이메일을 검토하고 수정한다.

            [Context]
            - 브랜드보이스 가이드: ...
            - 고객사 K CRM 정보: ...
            - 초안: ...

            [Constraints]
            - 브랜드보이스를 위반하지 말 것
            - CRM에 없는 사실은 만들지 말 것
            - 위반 사항을 먼저 전부 설명할 것

            [Format]
            1. 위반 사항
            2. 근거 문서
            3. 수정 이유
            4. 최종 이메일

- 2. chain of thought
  - 여러 숫자와 규칙을 단계적으로 연결하는 문제
  - 실제 문제는 경영지원팀의 Q3 마케팅 예산과 여러 인보이스를 찾아서

          각 인보이스 금액 확인
          ↓
          필요한 금액 합산
              ↓
          Q3 예산 확인
              ↓
          예산 - 지출 비교
              ↓
          초과 여부
              ↓
          초과 금액
              ↓
          규정상 처리 가능 범위 확인

    - AI한테 처음부터 “초과 금액 알려줘” 하면 문서를 빠뜨릴 수 있음 -> 관련 인보이스 문서가 총 몇 개인지 목록을 만들고, 각 금액을 표로 정리해라. 그다음 계산

      | 문서      | 금액 | 포함 여부 | 이유      |
      | --------- | ---: | --------- | --------- |
      | Invoice A |  ... | 포함      | Q3 마케팅 |
      | Invoice B |  ... | 포함      | Q3 마케팅 |
      | Invoice C |  ... | 제외      | 다른 부서 |

- Self consistency
  - 한 경로의 추론결과를 바로 믿지 말고, 다른 근거 경로에서도 같은 결론이 나오는지 확인

            0614 인시던트 문서 전체 수집

            경로 A
            포스트모템 초안
            → 장애 원인 후보

            경로 B
            배포로그 / 모니터링 기록 / 관련 변경
            → 장애 원인 후보

                    ↓

            A와 B 비교

            같음?
            ├─ YES → 신뢰도 증가
            └─ NO → 원문 재검토



        | 추론 경로 | 근거 문서            | 원인 후보      |
        | ----- | ---------------- | ---------- |
        | 경로 A  | postmortem_draft | 설정 변경      |
        | 경로 B  | deploy_log       | 동일 설정 변경   |
        | 결론    | 두 경로 일치          | 근본원인 확정 후보 |

    - 재발 방지 체크리스트, 포스트모템 작성자의 추정과 실제 로그가 일치하는가? 확인

- ReAct
  - 한번에 모든 답을 얻는 문제가 아니라 문서를 하나씩 따라감
  - 이 두 건을 하나의 지출 건으로 합산해서 봐야 하는가? -> 경비 처리규정에서 확인,
  - 경비처리규정 → 조직도 → 인사기록 → 최종 승인자

            [생각]
            합산 기준상 총 110만원으로 판단해야 한다.

            [행동]
            경비처리규정에서 110만원 승인 기준을 찾는다.

            [관찰]
            해당 금액은 특정 직급 승인이 필요하다.

            [다음 행동]
            조직도를 확인한다.

            [관찰]
            해당 부서 책임자/승인 직책을 확인한다.

            [다음 행동]
            인사기록을 확인한다.

            [최종]
            승인자 이름 확인.

    - 조직도만 보고 승인자 섣부르게 추측하지말고 문서가 다음 문서를 가리키면 실제로 그 문서를 확인해야됨

            규정 → 어떤 직책?
            조직도 → 그 직책은 누구?
            인사기록 → 현재 실제 담당자가 맞나?

- 5. Memory & Compaction
  - 문서가 많아졌을때 context를 어떻게 압축해서 유지할 것인가. 전부 AI한테 매번 다시 넣으면 Context가 길어지기 때문에,

          W01 읽음
          ↓
          핵심 상태 저장

          W02 읽음
          ↓
          기존 상태 + 변경사항 병합

          W03 읽음
          ↓
          변경된 내용만 업데이트

          ...

          W17
          ↓
          최종 compact summary

    - 보존해야되는 핵심 정보 예시

            일정
            PM
            예산
            주요 의사결정
            변경사항
            리스크
            확정사항
            미확정사항
            근거 문서

    - 과거 특정 시점의 정보를 나중에 다시 찾아오는 방법.압축된 상태 + 원문 위치를 같이 남기기

            현재 상태:
            PM = 홍길동

            변경 이력:
            W05: 김A → 홍길동 변경
            근거: W05_slack
