- 운영체제 : 프로그램과 하드웨어 사이의 중간 관리자
  - 디스크(비휘발성, 경로로 지정, 느림), 메모리(휘발성, 실제 연산 수행하는 공간, 빠름), cpu(명령을 처리)
  - 운영체제의 역할 중 하나 : 여러 프로그램마다 메모리사용 -> 메모리 구별 제어

- 가상화, 컨테이너
  - 커널(운영체제의 핵심 역할)
  - 하나의 컴퓨터를 여러개의 독립적으로 사용하고 싶다 -> 가상머신
  - 컨테이너
    - 동료컴퓨터랑 내 컴퓨터의 환경설정이 달라 실행이 정상적으로 안되는 경우
    - 가상머신의 한계 : 가상머신마다 os,커널 다 있음 -> 자원사용량증가 및 속도 감소
    - 호스트 Os랑 커널을 공유 : 격리(프로세스, 네트워크....), 독립 실행, 가벼움
    - 도커는 컨테이너 활용 도구
  - 이미지
    - 컨테이너를 실행하기 위한 패키지,틀,도구 -> 하나의 이미지로 여러 컨테이너 실행 가능
    - 도커 파일 빌드를 실행하면 이미지 만들어지고 이미지를 공용으로 쓸수있는 저장소에다 이미지만 올리면 이미지만 받아서 도커 실행 가능
    - 하나의 이미지로 여러 환경에서 동일한 컨테이너를 실행 가능함
- 스프링 흐름
  - 스프링 환경안에서 ai를 잘 구축
  - 야말에 설정값들 모아놓음 -> 민감 환경 : .env
  - 로컬 환경마다 설정 값이 다르다면? -> Profile(환경별 설정 파일 구분, 같은 이미지써도 다른 설정으로 분기 가능),실제로는 github action(github secrete(env설정 넣어둠))을 많이 씀, 쿠버네틱스 시크릿
  - Spring Ai : 서비스에서 호출, 스프링에서 ai사용하기 쉽게 만들어줌
