# 궁금한점

- 코드로 레그구조 잘 짜놓는거랑, 에이전트에 도구만 쥐여주고 흐름을 그냥 잘! 프롬프트로 구상해서 넘겨주는거랑 차이

            | 방식 | 코드로 흐름 고정 | Agent에게 도구 + 프롬프트 |
            |---|---|---|
            | 흐름 | 개발자가 결정 | LLM이 매번 결정 |
            | 일관성 | **높음** | 상대적으로 낮음 |
            | 예외 대응 | 미리 구현한 범위 | **유연함** |
            | 복잡한 탐색 | 코드가 복잡해짐 | **강점** |
            | 불필요한 Tool 호출 | 적음 | 발생 가능 |
            | 비용/속도 | **예측 가능** | 호출 수가 늘 수 있음 |
            | 디버깅 | **쉬움** | 왜 그런 선택을 했는지 추적 어려울 수 있음 |
            | 새로운 상황 | 코드 수정 필요 | **프롬프트만으로 대응 가능할 때도 있음** |

이미 정답에 가까운 절차를 우리가 알고 있다면 코드로 짜는 게 보통 더 안정적이고, 정답 절차 자체를 상황에 따라 찾아야 한다면 Agent에게 자유를 주는 게 유리하다.

그리고 요즘 Agent 설계에서 중요한 건 **“어떻게 더 자유롭게 만들까?”가 아니라 “어디까지만 자유롭게 둘까?”**에 더 가깝다.
우리 투자평가 프로젝트도 그래서 Graph가 전체 절차를 통제하고, 기술·시장·경쟁 분석 내부의 애매한 판단만 Agentic하게 만드는 것이 꽤 좋은 설계 방향
