# Spring Boot 게시판 + 생성형 AI 이미지 기능 최종 정리

## 0. 최종 정리 / 흐름 요약

### 한 문장 정리

기존 Spring Boot 게시판의 `Controller → Service → Repository → DB` 계층 구조는 유지하면서,  
별도의 `ImageController → ImageService → Cloudflare Workers AI(FLUX.1 Schnell)` 흐름을 추가해  
**게시글 작성 중 AI 이미지를 생성하고, 생성된 이미지는 서버 파일시스템에 저장하며, DB에는 이미지 경로만 저장하여 게시글 조회 시 함께 표시하도록 확장했다.**

### 전체 흐름

```text
사용자
  │
  │ 제목 / 내용 입력
  │ [이미지 생성] 클릭
  ▼
post-form.html / post-form.js
  │
  │ prompt
  ▼
POST /api/images/generate
  │
  ▼
ImageController
  │
  ▼
ImageService
  │
  │ HTTP 요청
  ▼
Cloudflare Workers AI
  │
  ▼
FLUX.1 Schnell
  │
  │ Base64 이미지 반환
  ▼
ImageService
  │
  ├─ Base64 → byte[]
  ├─ generated-images/*.jpg 저장
  └─ /api/images/{파일명}.jpg 반환
             │
             ▼
       post-form.js
             │
             ├─ 생성 이미지 미리보기
             └─ imageUrl 보관
                     │
                     ▼
       POST /api/posts
       title + content + imageUrl
                     │
                     ▼
              PostController
                     │
                     ▼
               PostService
                     │
                     ▼
              PostRepository
                     │
                     ▼
                  MariaDB
              posts.image_url
```

### 게시글 조회 흐름

```text
게시판에서 제목 클릭
        ↓
GET /api/posts/{id}
        ↓
PostController
        ↓
PostService
        ↓
PostRepository
        ↓
DB
        ↓
PostResponse
(title, content, writer, imageUrl ...)
        ↓
board.js
        ↓
내용 + AI 생성 이미지 표시
```

## 1. 시작 구조

교수님 게시판 코드는 기본적으로 다음 계층으로 구성되어 있었다.

```text
Browser
   ↓
PostController
   ↓
PostService
   ↓
PostRepository
   ↓
DB
```

각 계층의 역할은 다음과 같다.

- `PostController`
  - `/api/posts` 요청 처리
  - GET / POST / PUT / DELETE
  - HTTP 요청을 받고 Service 호출
  - 인증된 사용자는 `Authentication.getName()`으로 확인

- `PostService`
  - 게시글 생성 / 조회 / 수정 / 삭제
  - 작성자 검증
  - Repository 호출

- `PostRepository`
  - DB 저장 / 조회

- `Post`
  - 게시글 도메인 객체

기존 게시글은 다음 정보를 가지고 있었다.

```text
Post
├─ id
├─ title
├─ content
├─ writer
├─ createdAt
└─ updatedAt
```

## 2. 목표 기능

이번에 추가한 기능의 목표는 다음과 같다.

```text
게시글 작성
    ↓
[이미지 생성]
    ↓
프롬프트 입력
    ↓
생성형 AI 호출
    ↓
이미지 생성
    ↓
작성 화면에서 미리보기
    ↓
게시글 저장
    ↓
게시글 상세 조회 시 이미지 표시
```

처음부터 복잡하게 만들지 않고 다음 원칙을 사용했다.

> 이미지 파일 자체를 DB에 저장하지 않는다.

이미지는 서버의:

```text
generated-images/
```

폴더에 저장하고 DB에는:

```text
/api/images/xxxxxxxx.jpg
```

형태의 **이미지 경로 문자열만 저장**한다.

## 3. DB 변경

기존 `posts` 테이블에 이미지 경로를 저장할 컬럼을 추가했다.

```sql
ALTER TABLE posts
ADD COLUMN image_url VARCHAR(1000);
```

결과:

```text
posts
├─ id
├─ title
├─ content
├─ writer
├─ image_url
├─ created_at
└─ updated_at
```

중요한 점:

```text
DB에 실제 JPEG 데이터 저장 X
DB에는 이미지 경로만 저장 O
```

예:

```text
/api/images/19d8308f-xxxx-xxxx-xxxx.jpg
```

## 4. Post 도메인 변경

기존 `Post`에 이미지 URL 필드를 추가했다.

```java
@Column(name = "image_url", length = 1000)
private String imageUrl;
```

결과:

```text
Post
├─ id
├─ title
├─ content
├─ writer
├─ imageUrl
├─ createdAt
└─ updatedAt
```

생성자도 이미지 URL을 받을 수 있도록 변경했다.

```java
public Post(
        String title,
        String content,
        String writer,
        String imageUrl
) {
    this.title = title;
    this.content = content;
    this.writer = writer;
    this.imageUrl = imageUrl;
    this.createdAt = LocalDateTime.now();
    this.updatedAt = this.createdAt;
}
```

getter:

```java
public String getImageUrl() {
    return imageUrl;
}
```

## 5. PostCreateRequest 변경

기존 DTO:

```text
PostCreateRequest
├─ title
└─ content
```

변경 후:

```text
PostCreateRequest
├─ title
├─ content
└─ imageUrl
```

```java
public record PostCreateRequest(
        @NotBlank(message = "제목을 입력해주세요.")
        @Size(max = 200, message = "제목은 200자 이하여야 합니다.")
        String title,

        @NotBlank(message = "내용을 입력해주세요.")
        String content,

        String imageUrl
) {
}
```

`imageUrl`에는 `@NotBlank`를 붙이지 않았다.

이유:

```text
AI 이미지 생성 안 함 → imageUrl = null 허용
AI 이미지 생성함     → imageUrl 값 저장
```

Java `record`이므로 자동으로 다음 메서드가 만들어진다.

```java
request.title()
request.content()
request.imageUrl()
```

## 6. PostResponse 변경

게시글 조회 결과에도 이미지 경로가 포함되어야 하므로 `PostResponse`에 `imageUrl`을 추가했다.

```java
public record PostResponse(
        Long id,
        String title,
        String content,
        String writer,
        String imageUrl,
        LocalDateTime createdAt,
        LocalDateTime updatedAt
) {
}
```

`PostResponse.from()`:

```java
return new PostResponse(
        post.getId(),
        post.getTitle(),
        post.getContent(),
        post.getWriter(),
        post.getImageUrl(),
        post.getCreatedAt(),
        post.getUpdatedAt()
);
```

### 발생했던 오류

`record` 선언 순서와:

```java
new PostResponse(...)
```

의 인자 순서가 다르면 constructor 오류가 발생한다.

즉:

```text
record 선언 순서
        =
new PostResponse() 인자 순서
```

가 되어야 한다.

## 7. PostService 변경

게시글 생성 시 `imageUrl`도 Domain 객체로 전달하도록 변경했다.

```java
@Transactional
public PostResponse create(
        PostCreateRequest request,
        String username
) {
    Post post = new Post(
            request.title(),
            request.content(),
            username,
            request.imageUrl()
    );

    return PostResponse.from(
            postRepository.save(post)
    );
}
```

흐름:

```text
PostCreateRequest
      ↓
PostService.create()
      ↓
new Post(title, content, writer, imageUrl)
      ↓
PostRepository.save()
      ↓
DB
```

### 중요한 포인트

`PostController`는 이미:

```java
@Valid @RequestBody PostCreateRequest request
```

를 받고 있었기 때문에 DTO에 `imageUrl`을 추가해도 Controller 구조를 크게 바꿀 필요가 없었다.

즉:

```text
JSON 데이터 확장
    ↓
DTO 확장
    ↓
Controller 거의 그대로
    ↓
Service에서 새로운 데이터 사용
```

이 가능했다.

## 8. 글쓰기 화면 변경

기존 `post-form.html`에는 제목 / 내용 / 저장 기능만 있었다.

여기에:

```text
[이미지 생성]
```

버튼과 이미지 미리보기 영역을 추가했다.

예:

```html
<label>AI 이미지</label>

<button id="generateImageButton" type="button" class="secondary-button">
  이미지 생성
</button>

<p id="imageStatus"></p>

<div id="imagePreview" hidden>
  <img
    id="generatedImage"
    alt="AI 생성 이미지"
    style="max-width: 100%; margin-top: 12px;"
  />
</div>
```

### `type="button"`을 사용한 이유

버튼이 `<form>` 내부에 있기 때문에:

```html
<button></button>
```

만 사용하면 submit 동작으로 이어질 수 있다.

따라서 이미지 생성 버튼은:

```html
type="button"
```

으로 설정했다.

```javascript
const generateImageButton = document.querySelector("#generateImageButton");
```

```text
    ↓

    ↓
```

```javascript
{
```

## 11. ImageController 역할

이미지 생성 요청:

```text
POST /api/images/generate
```

요청 예:

```json
{
  "prompt": "우주에서 Java 코딩을 하는 로봇"
}
```

Controller 흐름:

```text
prompt
  ↓
ImageService.generate(prompt)
  ↓
imageUrl 반환
  ↓
JSON 응답
```

응답:

```json
{
  "imageUrl": "/api/images/xxxxxxxx.jpg"
}
```

또한 실제 저장된 이미지를 브라우저에 제공하기 위해:

```text
GET /api/images/{fileName}
```

엔드포인트도 사용한다.

## 12. ImageService 역할

최종 `ImageService`의 핵심 역할:

```text
prompt 받기
    ↓
Cloudflare Workers AI REST API 호출
    ↓
FLUX.1 Schnell 이미지 생성
    ↓
Base64 응답
    ↓
Base64 → byte[]
    ↓
generated-images/*.jpg 저장
    ↓
/api/images/{fileName}.jpg 반환
```

즉 Java가 직접 이미지를 생성하는 것이 아니다.

```text
Java / Spring
    ↓
외부 AI 모델 호출
    ↓
AI 결과 관리
```

역할을 한다.

## 13. Cloudflare Workers AI 연결

최종 생성형 AI 서비스:

```text
Cloudflare Workers AI
        ↓
FLUX.1 Schnell
```

를 사용했다.

환경변수:

```text
CLOUDFLARE_API_TOKEN
CLOUDFLARE_ACCOUNT_ID
```

Spring에서는:

```java
System.getenv("CLOUDFLARE_API_TOKEN");
System.getenv("CLOUDFLARE_ACCOUNT_ID");
```

로 읽는다.

### 환경변수를 사용한 이유

다음처럼 API 키를 직접 Java / JavaScript에 넣으면 안 된다.

```java
String apiKey = "실제 API 키";
```

특히 프론트 JavaScript에 키가 들어가면 브라우저에서 그대로 노출된다.

따라서:

```text
터미널 환경변수
      ↓
Spring Boot
      ↓
외부 API 호출
```

구조로 사용했다.

## 14. generated-images 폴더

Cloudflare가 반환한 Base64 이미지를 실제 파일로 변환해:

```text
generated-images/
├─ uuid1.jpg
├─ uuid2.jpg
└─ uuid3.jpg
```

형태로 저장한다.

### 왜 resources/static에 저장하지 않았나?

현재 Spring Boot 프로젝트는:

```bash
./gradlew clean bootJar
java -jar ...
```

형태로 실행한다.

`src/main/resources/static` 파일들은 빌드 시 JAR 내부에 포함된다.

반면 AI 이미지는 프로그램 실행 중 동적으로 생성되므로:

```text
generated-images/
```

같은 JAR 외부 파일시스템에 저장하는 것이 자연스럽다.

## 17. 외부 AI 제공자를 여러 번 바꿔본 과정

처음에는 OpenAI 이미지 생성 API를 사용했다.

흐름 자체는:

```text
Browser
→ Controller
→ Service
→ OpenAI API
```

까지 정상 동작했지만:

```text
Billing hard limit has been reached
```

오류가 발생했다.

즉 코드 구조 문제가 아니라 API 결제 문제였다.

다음으로 Pollinations를 테스트했다.

파일은 생성됐지만:

```bash
file pollinations-test.jpg
```

결과가:

```text
JSON data
```

였다.

파일 내용:

```text
Insufficient balance
```

즉 `.jpg` 확장자를 가지고 있어도 실제 응답이 이미지라는 보장은 없다는 점을 확인했다.

최종적으로 Cloudflare Workers AI로 교체했고 이미지 생성에 성공했다.

### 여기서 얻은 아키텍처 관점의 의미

외부 AI 제공자가:

```text
OpenAI
   ↓
Pollinations
   ↓
Cloudflare
```

로 변경되어도 기존:

```text
PostController
PostService
PostRepository
board.js의 게시판 구조
```

전체를 뜯어고칠 필요가 없었다.

주로:

```text
ImageService
```

의 외부 호출 부분만 교체했다.

이것이 기능을 계층과 역할로 분리하는 이유 중 하나다.

## 18. 구현 중 발생했던 주요 오류

### 18.1 `request.imageUrl()` undefined

원인:

`PostCreateRequest`에 아직:

```java
String imageUrl
```

이 없었다.

해결:

DTO에 `imageUrl` 추가.

### 18.2 PostResponse constructor 오류

원인:

```text
record 선언 순서
```

와:

```text
new PostResponse(...)
```

인자 순서가 달랐다.

해결:

두 순서를 동일하게 맞춤.

### 18.3 PageController package 빨간줄

실제 파일 위치:

```text
src/main/java/loginauth/global/config/web/PageController.java
```

package:

```java
package loginauth.global.web;
```

이 서로 달랐다.

Java 패키지 구조는:

```text
package loginauth.global.web;
        ↕
src/main/java/loginauth/global/web/
```

처럼 일치시키는 것이 기본이다.

파일을:

```text
src/main/java/loginauth/global/web/PageController.java
```

로 옮겨 해결했다.

### 18.4 수정했는데 화면이 그대로였음

원인:

- 이전 JAR가 계속 실행 중이었거나
- 새로 빌드된 정적 리소스가 반영되지 않은 상태

해결:

```bash
Ctrl + C
./gradlew clean bootJar
java -jar build/libs/...
```

후 브라우저 강력 새로고침.

Mac Chrome:

```text
Cmd + Shift + R
```

## 19. 교수님 수업 의도와 연결

이번 실습의 가장 중요한 부분은 **Java로 AI 모델을 만든 것이 아니라는 점**이다.

실제 이미지 생성은:

```text
FLUX.1 Schnell
```

이 담당한다.

Java/Spring이 담당한 부분:

```text
누가 AI를 사용할 것인가?
        ↓
어떤 데이터를 AI에 보낼 것인가?
        ↓
어느 AI 서비스를 호출할 것인가?
        ↓
결과를 어떻게 받을 것인가?
        ↓
결과를 어디에 저장할 것인가?
        ↓
기존 업무 기능과 어떻게 연결할 것인가?
        ↓
사용자에게 어떻게 제공할 것인가?
```

즉 Java는 **AI 서비스의 백엔드 중심** 역할을 한다.

이 관점에서는 코드 문법 하나하나보다 다음을 보는 것이 중요하다.

1. 이 객체의 역할은 무엇인가?
2. 어디서 데이터를 받는가?
3. 누구에게 일을 넘기는가?
4. 무엇을 반환하는가?
5. 인증 / DB / 예외 / AI 호출은 각각 어디에서 담당하는가?
6. 새로운 AI 기능을 붙이면 어느 계층에 들어가는가?

---

## 20. 이번 실습에서 확인한 계층형 아키텍처의 의미

기능별 역할을 분리했기 때문에:

```text
게시판 업무 로직
```

과:

```text
AI 이미지 생성 로직
```

이 서로 강하게 섞이지 않았다.

따라서 AI 제공자를 변경하거나 기능을 확장해도 기존 게시판 구조를 크게 수정하지 않아도 된다.

```text
기존 업무 기능
+
새로운 AI 기능
```

을 독립적으로 만든 후 필요한 지점에서 연결하는 방식이다.

## 22. 최종 핵심 요약

### 구현 결과

- 기존 게시판 계층 구조 유지
- 게시글 작성 화면에 `이미지 생성` 버튼 추가
- 사용자 프롬프트 입력
- Spring Boot에서 Cloudflare Workers AI 호출
- FLUX 모델로 이미지 생성
- Base64 결과를 JPEG로 저장
- DB에는 이미지 자체가 아닌 URL/경로만 저장
- 게시글 상세 조회 시 생성 이미지 출력

### 아키텍처 관점

```text
Spring Boot
=
AI 모델 자체

가 아니라

Spring Boot
=
기존 업무 시스템
+
데이터
+
인증
+
DB
+
외부 AI 모델
을 연결하고 제어하는 백엔드
```

### 한 줄 회고

> 기존 Spring Boot 게시판에 생성형 AI 이미지 기능을 별도 서비스로 추가하면서, Java/Spring이 AI 모델을 직접 구현하기보다 기존 업무 데이터와 외부 AI 모델을 연결하고 제어하는 AI 서비스 백엔드 역할을 한다는 점을 확인했다.
