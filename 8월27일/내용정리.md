- sLLM(소형 언어 모델) 효율적 관리 및 운영 팁
  - sLLM(Small Language Model)은 대형 언어 모델(LLM)에 비해 적은 파라미터를 가지고 있어 비용이 저렴하고 속도가 빠르며, 특정 도메인(업무 분야)에 맞게 커스텀하기 용이하다는 장점이 있습니다.
  1. 양자화(Quantization)를 통한 경량화 및 자원 최적화
     - 개념: 모델의 가중치(Weight) 정밀도를 낮추어(예: FP16에서 INT8, INT4로 변환) 메모리 사용량을 대폭 줄이고 추론 속도를 높이는 기법입니다.
     - 추천 도구: AWQ, GPTQ, GGUF 등의 포맷과 llama.cpp, vLLM 같은 추론 엔진을 활용하면 GPU 메모리가 부족한 환경에서도 효율적으로 서빙할 수 있습니다.

  2. 고품질 도메인 데이터 선별 및 파인튜닝(Fine-Tuning)
     - 데이터 정제: sLLM은 파라미터 규모가 작기 때문에 학습 데이터의 '양'보다 '질'이 성능을 좌우합니다. 잡음(Noise)이 섞인 데이터를 제거하고, 명확하고 구조화된 지시어(Instruction) 데이터셋을 구축해야 합니다.
     - 효율적 학습 방법: 전체 모델을 학습하는 Full Fine-Tuning 대신 QLoRA(Quantized Low-Rank Adaptation) 또는 LoRA 기법을 적용하면, 적은 컴퓨팅 자원과 시간으로도 뛰어난 도메인 적응형 모델을 만들 수 있습니다.

  3. RAG(검색 증강 생성)와의 결합
     - 환각 현상(Hallucination) 방지: sLLM은 대형 모델에 비해 지식 베이스가 상대적으로 좁기 때문에, 최신 정보나 사내 문서를 정확히 반영하기 어렵습니다.
     - 구현 방식: 벡터 데이터베이스(Vector DB)와 연동된 RAG 파이프라인을 구축하여, 질문과 관련된 외부 문서나 가이드를 먼저 검색한 뒤 모델이 그에 기반해 답변을 생성하도록 관리하세요.

  4. 고성능 추론 및 서빙 프레임워크 도입
     - vLLM / TGI 활용: 일반적인 Hugging Face Transformers 코드로 서빙하는 것보다, vLLM(PagedAttention 적용으로 메모리 효율 극대화)이나 TGI(Text Generation Inference) 같은 전용 서빙 엔진을 사용하면 동시 요청 처리량(Throughput)과 응답 속도가 크게 향상됩니다.
     - 캐싱 적용: 반복적으로 들어오는 유사한 질문이나 시스템 프롬프트에 대해 KV Cache 등을 적극 활용하여 연산 부하를 줄입니다.

  5. 지속적인 평가(Evaluation)와 모니터링
     - 벤치마크 및 커스텀 평가셋: 모델을 경량화하거나 파인튜닝한 후에는 반드시 사내 기준에 맞는 테스트셋(예: 정확도, 응답 속도, 보안 유출 여부 등)을 통해 성능 저하가 없는지 평가해야 합니다.
     - 로깅 및 피드백 루프: 실사용자의 피드백(좋아요/싫어요, 수정 요청 등)을 수집하여 잘못된 응답 패턴을 파악하고, 이를 다음 데이터셋 업데이트와 재학습(Continuous Learning)에 반영하는 체계를 마련하세요.

- sLLM 파인튜닝(Fine-Tuning) 전략 가이드
  - 소형 언어 모델(sLLM)의 성능을 특정 도메인이나 목적에 맞게 극대화하기 위한 핵심 파인튜닝 전략을 정리해 드립니다.
  1. 학습 방식 선택 (Parameter-Efficient Fine-Tuning, PEFT)
     - 전체 모델 파라미터를 학습하는 Full Fine-Tuning은 막대한 컴퓨팅 자원이 필요하므로, sLLM 환경에서는 효율적인 파라미터 튜닝 기법을 우선적으로 고려합니다.
     - LoRA (Low-Rank Adaptation): 모델의 기존 가중치는 동결(Freeze)하고, 저랭크(Low-Rank) 행렬 소스만 추가하여 학습하는 방식입니다. GPU 메모리 사용량을 대폭 줄이면서도 Full Fine-Tuning에 준하는 성능을 낼 수 있어 가장 널리 쓰입니다.
     - QLoRA (Quantized LoRA): 기본 모델을 4비트(4-bit) 등으로 양자화하여 메모리 점유를 최소화한 상태에서 LoRA를 적용하는 기법입니다. 일반적인 소비자용 GPU 환경에서도 대형 모델 수준의 sLLM을 파인튜닝할 수 있게 해줍니다.

  2. 데이터셋 구축 및 정제 전략 (Data Curation)
     - sLLM은 파라미터 규모가 작기 때문에 데이터의 '양'보다 '질'이 성능을 결정짓는 핵심 요소입니다.
     - 인스트럭션 튜닝(Instruction Tuning) 데이터:[System Prompt], [User Instruction], [Response] 구조로 명확하고 일관된 형식의 데이터셋을 구성합니다.
     - 데이터 품질 관리 (Noise 제거): 오탈자, 잘못된 답변, 문맥이 어긋나는 데이터는 모델의 환각(Hallucination)을 유발하므로 철저히 필터링합니다.
     - 합성 데이터(Synthetic Data) 활용: 도메인 데이터가 부족할 경우, 대형 모델(GPT-4 등)을 활용해 고품질의 학습용 인스트럭션 데이터셋을 생성·정제하여 활용합니다.

  3. 하이퍼 파라미터 및 학습 설정 최적화
     - 학습률(Learning Rate): PEFT/LoRA 적용 시 일반적으로 1e-4에서 2e-4 사이의 학습률로 시작하며, 과적합(Overfitting)을 막기 위해 코사인 스케줄러(Cosine Scheduler)와 적절한 Warmup 단계를 설정합니다.
     - 배치 사이즈(Batch Size) & 가중치 누적(Gradient Accumulation): 제한된 GPU 메모리 환경에서는 작은 배치 사이즈를 유지하되, Gradient Accumulation을 통해 실효 배치 사이즈를 키워 학습 안정성을 높입니다.
     - 프롬프트 템플릿 일관성: 사전 학습(Pre-training)이나 베이스 모델이 요구하는 고유의 토크나이저 및 프롬프트 템플릿(Chat Template) 형식을 학습 과정에서도 정확히 유지해야 합니다.
  4. 평가 및 검증 전략 (Evaluation)
     - 검증셋(Validation Set) 분리: 학습 데이터에만 과적합되어 실제 업무 환경에서 엉뚱한 답변을 내놓는 것을 방지하기 위해, 도메인 특화 평가셋을 별도로 분리해 주기적으로 체크합니다.
     - LLM-as-a-Judge 활용: 정량적 지표(Perplexity 등) 외에도, 파인튜닝된 모델의 응답 품질을 GPT-4 같은 상위 모델이나 전문가 평가 프레임워크를 통해 비교·검증합니다.

- 실습 : 패딩처리(+endoftext), 마스킹 처리(ignore_index = -100, endoftext토큰은 남기기), 파인튜닝, 퀀타이제이션, loRA
  - 가장 중요한 것은 이전에 정확히 맞은 스팸/스팸아닌 클래스 레이블의 비율을 계산하여 분류 정확도를 얻었던 것처럼 모델 평가가 간단하지 않다는 것임
  - 실제로 챗봇과 같은 지시 미세튜닝 llm 은 여러 접근 방식을 통해 평가

# 궁금한 점

- 오픈소스 모델들을 활용해서 내가 효율화를 할 수 있는 지점과 기술 정리

| 목표                   | 대표 기술                  |
| ---------------------- | -------------------------- |
| 애초에 작은 모델       | 작은 B 모델 선택           |

| 모델 메모리 감소       | **Quantization**           |
| 파라미터 자체 감소     | **Distillation / Pruning** |

| 생성 중 중복 계산 감소 | **KV Cache**               |
| 서버 처리량 증가       | **Batching / vLLM**        |
| 큰 모델 분산           | Tensor Parallel 등         |

- 상업적으로도 이용이 가능하게 오픈소스 모델을 열어두는 회사가 많다 왜그런가?

열어두면 도구, 효율화, 실리콘 최적화, 통합 생태계가 함께 발전하고, 자신들도 그 결과를 다시 활용할 수 있다는 논리

모델을 공개하면 전 세계 개발자들이 그 모델 위에 LoRA를 붙이고, 양자화 버전을 만들고, 툴을 연결하고, 서빙 최적화를 함. 그러면 자연스럽게 그 모델이 사실상의 표준처럼 자리 잡을 수 있다. 실제로 Qwen 계열은 파생 모델과 변형이 매우 많이 만들어지면서 생태계 자체가 커졌고, Hugging Face도 이런 오픈웨이트 전략이 API·클라우드·플랫폼 포지션 같은 다른 곳에서 가치를 회수하는 구조

오픈웨이트 모델은 전형적인 “모델을 미끼로 다른 인프라/서비스에서 수익화” 전략도 가능. 실제 업계 분석에서도 open model의 수익 회수 지점으로 API, 클라우드, 하드웨어, 플랫폼 영향력을 많이 꼽는다.

- Gradient Accumulation?

Gradient Accumulation = 작은 batch 여러 번의 gradient를 쌓아서, 큰 batch 한 번처럼 가중치를 업데이트하는 기법.
