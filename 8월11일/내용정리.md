- ref()
  - 모든 값을 반응형 상태로 만든다
  - 스크립트 셋업에서는 .value(ref객체 이기 떄문), 템플릿에서는 `{{}}`
  - reactive()
    - 참조 자료형을 반응형 상태로 만듬 -> 스크립트에서 접근할때 .value.~ 없이 바로 .~ 접근
    - 반응성 단절 : 반응형 객체를 교체하거나 구조를 분해햐야 할당하면 반응성 연결이 끝ㄴㅎ어진다
  - 따라서 실무에선 ref로 통일하는 추세

- computed() : 의존하는 반응형 데이터가 변경될때만 자동으로 다시 계싼된다
  - const 식별자 = computed(() => {return 값})
  - 바꿀 수 없음
  - 온도 평균값? 최저 기온의 도시는?

- watch()
  - 반응형 데이터의 값이 변경되었을때 후속 로직(비동기 통신, 데이터 저장 등)을 수행
  - watch(반응형데이터, (newVal, oldVal) => { 실행할 후속 로직 })
  - 특정 날씨온도? 같은거 나오면 후속조치(api조회 연결?)
  - watch([반응형 데이터, 반응형데이터2], ([ new , old ], [ new , old ]) => {로직})
  - deep Watch
    - ref()로 선언된 객체나 배열을 감시할 때 쓰는 기법(객체의 주소는 안바뀌기때문에 감시를 못하기 떄문)(oldVal안받음, 추적불가)
    - ...(newVal)...{로직},{deep:true}
    - 객체의 특정값만 보고싶다?
      - watch(() => 변수.value.속성, (new, old)=>{로직})
    - reative() 객체는 deep watch안해도됨, 그거 외에 ref랑 큰 차이는 없음
  - 배열의 특정 값을 보고싶다 ( () => 배열.value[0] 사용)
  - ref 객체형 배열의 특정 객체 내부 속성을 감시할때 응용
  - watchEffect 감시 대상을 명시 하지 않아도 자동으로 바꿈, 컴포넌트가 첫실행때도 무조건 즉시 실행, old 못씀
    - watchEffect(() => {여기 코드를 읽고 자동으로 감시리스트에 등록})
