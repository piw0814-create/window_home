- 1단계: Spring Boot 소스 코드 준비
- 2단계: 로컬에서 Buildah·BuildKit·Kaniko로 이미지 빌드
- 3단계: Kubernetes Pod로 빌드 환경 이전 : 로컬 PC가 아닌 Kubernetes에서 이미지 빌드 수행
- 4단계: Init Container와 Main Container로 빌드 과정 분리 : 애플리케이션 빌드와 컨테이너 이미지 빌드를 분리
- 5단계: 공유 Volume과 Secret을 활용해 Harbor Push 연결 : 컨테이너 간 빌드 결과물을 전달하고 Registry 인증 처리, 두 컨테이너가 동일한 /workspace를 마운트, Kubernetes Secret — Harbor 인증
- Init Container에서 JAR 생성 → Main Container에서 이미지 생성 → 나중에 해당 이미지로 Spring Boot 실행

- kustomize
  - 원본 yaml은 순수 쿠버네티스 표준 문법 그대로 두고 변경이 필요한 차이점만 별도 파일로 덮어 씌움
  - based + overlay -> final manifests
  - Kustomize는 공통 Kubernetes YAML에 환경별 변경 사항을 적용해 최종 배포 설정을 생성하는 도구이고, kustomization.yaml은 그 조합 규칙을 정의하는 파일.
    -     | 파일 | 역할 |
          |---|---|
          | `base/deploy.yaml` | Deployment 기본 설정 |
          | `base/service.yaml` | Service 기본 설정 |
          | `base/kustomization.yaml` | 공통 리소스 목록 지정 |
          | `dev/kustomization.yaml` | 개발 환경에 적용할 설정 통합 |
          | `dev/patch-deployment.yaml` | Deployment 설정 일부 변경 |
          | `dev/configmap.yaml` | 개발 환경 설정값 정의 |



          ① overlays/dev/kustomization.yaml 읽기
                          │
                          ▼
          ② resources 확인
          ├── ../../base
          └── configmap.yaml
                          │
                          ▼
          ③ base/kustomization.yaml 읽기
          ├── deploy.yaml

                          ▼

          ⑥ 최종 Kubernetes YAML 생성

  - Jenkinsfile
    - 젠킨스 파이프라인을 코드 정의한 스크립트 파일
    - environment : ",' 차이, 고정 문자열은 ' ', Groovy 변수 치환이 필요할 때만 " " 사용. sh에서는 환경변수를 Shell이 처리하게 ' '를 선호.
    - option : 파이프라인, 또는 특정 stage의 실행 방식을 제어하는 옵션
    - stages :
      - agent any = 이 Pipeline 전체를 실행할 수 있는 Jenkins Agent 아무 곳에서나 실행해라.
      - step 실제 작업을 수행하는 가장 작은 실행 명령 단위
    - post
    - Jenkinsfile에 어디서(agent), 어떤 변수로(environment), 어떤 정책으로(options), 어떤 단계(stages)를 거쳐, 무슨 명령(steps)을 실행하고, 결과 후 무엇을 할지(post) 정의하며, 필요한 로그인 정보는 Credentials에서 안전하게 꺼내 쓴다.
