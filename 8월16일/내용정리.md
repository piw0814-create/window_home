- 요구사항 정의서 주요 작성 항목
  - 기본 정보
    - 프로젝트명/작성자/작성일자/버전
    - 요구사항 ID : 식별을 위한 고유 식별 코드
    - 분류(카테고리): 회원관리, 결제, 대시보드, 시스템 관리등
  - 기능 요구사항
    - 시스템이 무엇을 해야하는지에 대한 직접적인 기능설명
    - 요구사항명 : 해당기능의 대표 명칭(예 : 소셜로그인기능)
    - 상세 설명 : 기능의 작동방식, 입력값, 출력결과, 예외처리 조건 등
    - 수요자/요청자 : 해당 기능을 요청한 주체(고객사, 마케팅팀 등)
    - 우선순위 : 필수/권장/선택
    - 난이도 및 공수 : 상/중/하 또는 MAN-DAY
  - 비기능 요구사항
    - 성능, 보안, 호환성 및 인프라, 유지보수성 및 신뢰성

  - ID : REQ-F-001 - 회원 - 가입 - 소셜 로그인 - 카카오/네이버 계정을 통한 간편 가입 및 로그인을 지원 - high - 중 - OAuth 2.0 API연동(비고/제약사항)

- 와이어 프레임/화면 설계서 작성 가이드
  - 와이어프레임을 작성할 때는 단순히 화면 그림만 그리는 것이 아니라, 화면 내 모든 요소의 동작 조건을 명확히 정의하는 것이 핵심
  - 화면 ID체계화 : 모든 화면에 고유한 ID를 부여하여 요구사항 정의서 및 개발 이슈와 1대1로 매핑되도록 구성
  - 그레이 스케일 활용 : 디테일한 컬러나 화려한 그래픽 요소 배제, 레이아웃, 정보구조, UX흐름에 집중
  - 디스크립션의 구체화 : 화면 내 각 요소(버튼 ,입력, 폼, 리스트 등)에 번호를 붙이고, 오른쪽 또는 하단에 해당 요소의 상태와 작동조건을 상세히 기록

- 화면 설계서 상세 기재 항목
  - 화면ID/화면명/작성자/작성일/최종 수정일/버전
  - depth경로, 수정이력
  - 추적성 체계
  - 요구사항 -> 와이어프레임 : 요구사항마다 해당 기능이 구현될 대상 화면 ID를 명시
  - 와이어프레임 -> 요구사항 정의서 : 화면 설계서의 디스크립션 화면에 연관된 요구사항 ID를 기입
