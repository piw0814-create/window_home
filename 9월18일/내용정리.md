# 예습

            사용자 질문
                │
                ▼
            Message History
                │
                ▼
            Prompt
                │
                ▼
            LLM
                │
                ├────→ 구조화 출력
                │       category
                │       urgency
                │
                ▼
            응답

- ① LLM을 파이프라인으로 묶고
- ② 출력 형식을 통제하고
- ③ 대화 상태를 유지한다

- 흐름을 개발자가 미리 정할 수 있다 → Chain
- 모델이 어떤 Tool을 쓸지,몇 번 반복할지 스스로 정해야 한다 → Agent

- Runnable = LangChain 부품들의 공통 실행 규격

- | = Runnable들을 연결

- invoke = 하나 실행
- stream = 생성되는 대로 받기
- batch = 여러 개 처리

- Prompt = 모델에게 보낼 입력 구성
- Model = LLM
- Parser = 결과 가공

# 수업내용

- 공통 조립 블록 8가지 패턴
  - 지도(Map)
    - 기본 파이프라인, 구조화 출력, 대화 메모리
  - 행동 + 안정성
    - Tool binding, 안정성(재시도, fallback), 복합chain
    - LangSmith로 진단
  - 지식+자율성+확장
    - rag, agent
    - langChain langGragh비교

- LangChain : LLM호출 프롬프트 메모리 도구 검색을 하나의 표준 인터페이스(Runnable)로 조립할 수 있게 해주는 오케스트레이션 프레임워크
  - Runnable 인터페이스만 잘 조립해서 쓰면 LLM 잘 쓸 수 있음
  - LangChain은 전체 프레임워크, Runnable은 그 안의 부품들이 공통으로 따르는 실행 인터페이스(invoke/stream/batch)
  - 표준화, 생태계, 이식성
  - 핵심 아키텍처
    - Model I/O, LCEL(Chains), Memory, Tool, Retriever, -> Runnable(invoke/stream/batch)로 연결,동작
  - LCEL
    - chain = ...|...|... -> chain.invoke("topic": "LangChain")
    - 조립 블록 : 기본 파이프라인, 구조화 출력, 대화 메모리, 툴, 안정성, 복합chain, rag, agent

- 패턴1. 기본 파이프라인
  - 가장 기본 LCEL : 프롬프트템플릿|모델|아웃풋파서 -> Runnable 로 실행
- 패턴2. 구조화 출력
  - wiith_structured_output()으로 Pydantic 모델을 지정해 모델이 바로 구조화된 객체를 반환하게함
- 패턴3. 대화 메모리
  - RunnableWithMessageHistory로 세션 ID별 대화 히스토리를 자동 저장·주입
