- entrypoint : 실행할 메인 프로그램을 고정
  - why? : 이미지의 주 목적이 되는 실행 프로그램을 고정하고, 실행할 때 옵션만 유연하게 바꾸기 위해서
  - ENTRYPOINT는 컨테이너의 핵심 실행 프로그램을 고정하고, CMD는 그 프로그램에 줄 기본 인자나 덮어쓸 수 있는 기본값으로 사용하는 경우가 많다
- 레이어 쌓기: run, copy, add
- 볼륨 타입 : Named Volume, Bind Mount
- CMD 한줄 잘못 사용하는 경우, 트래픽을 받고 처리 중 Graceful shutdown 되지 않고 KILL 되는 현상 발생
- Frontend(Nginx), Backend(Spring Boot), Database(MariaDB)를 각각 독립적인 Docker 이미지/컨테이너로 구성하고, 동일한 Docker Network에서 컨테이너 이름을 이용해 서로 통신
- container feature
  - namespace : 프로세스 마다 서로 다른 시스템 뷰 제공, PID,NET,...
  - cgroups : 자원 사용을 통제, 하나의 컨테이너가 폭주해도 노드 전체에 영향을 최소화
  - rootfs + OverlayFs : 이미지 레이어를 모든 컨테이너와 재사용, 컨테이너마다 독립 파일 시스템으로 격리
  - Netfliter : 네트워크 패킷을 가로채고, 검사하고, 변경 지원
  - Linux Capabilities : 프로세스가 어떤 시스템 작업을 수행할 수 있는가, 루트 권한을 세분화
  - SELinux/AppArmor : 프로세스가 어떤 대상에 접근할 수 있나, 컨테이너가 호스트의 불필요한 시스템 자원에 접근하는것을 차단
- Namespace = 격리, cgroups = 자원 제한, OverlayFS = 파일시스템 격리/재사용, Netfilter = 네트워크 제어, Capabilities·SELinux/AppArmor = 권한·보안 제어
- OverlayFS는 읽기 전용 lower 레이어와 쓰기 가능한 upper 레이어를 합쳐 하나의 파일시스템처럼 보여주며, lower 파일을 수정하면 원본을 건드리지 않고 upper로 Copy-up한 뒤 수정한다.
- dockerd (Docker Engine): 우리가 입력한 docker run, -p, -e, --memory, --network 같은 요청을 받아서 전체 Docker 작업을 조율하는 상위 관리자. 실제 저수준 컨테이너 생성 작업은 containerd에 넘김.
- containerd: 이미지를 준비하고 OverlayFS 등을 이용해 컨테이너가 볼 rootfs를 준비하고, 실행 옵션을 OCI 표준의 config.json 형태로 구성. 그다음 실제 실행을 shim/runtime 쪽에 맡김.
- containerd-shim: containerd와 실제 컨테이너 프로세스 사이에서 컨테이너를 계속 관리하는 중간 관리자. 컨테이너 PID, 종료 상태, 표준 입출력 등을 관리해서 docker logs, docker exec 같은 기능이 가능하도록 연결.
- runc: 실제로 Linux 커널에 명령해서 컨테이너 환경을 만드는 저수준 OCI runtime. namespace를 만들고, cgroups를 설정하고, 준비된 rootfs를 컨테이너의 /로 보이게 한 뒤 최종 애플리케이션 프로세스를 실행. 컨테이너가 실행된 뒤 runc 자체는 보통 종료하고, 이후 관리는 shim이 담당.
- container process: 최종적으로 우리가 Dockerfile의 CMD/ENTRYPOINT로 지정한 java, python, nginx 같은 실제 애플리케이션 프로세스가 실행.
- dockerd가 전체를 지휘하고 → containerd가 실행 준비를 하고 → runc가 Linux 커널 기능을 이용해서 실제 컨테이너를 만들고 → shim이 실행된 컨테이너를 계속 관리한다.
- docker-compose

# 궁금한점

- 심이 필요한 이유?

shim이 있기 때문에 containerd의 생명주기와 실제 컨테이너 프로세스의 생명주기를 분리할 수 있다.

            containerd
            = "컨테이너 전체를 관리하는 관리자"

            runc
            = "컨테이너를 실제로 만들어주는 작업자"

            shim
            = "만들어진 컨테이너 옆에 남아서
            계속 상태를 봐주는 담당자"
