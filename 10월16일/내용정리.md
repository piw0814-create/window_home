- error
  - transient, permanent, recoverable, Non-recoverable, user error system error
  - 에러를 모두 같은 방식으로 처리하면 안됨, 각 종류에 맞는 전략 필요
  - error responsibility
    - 하위 layer -> 상위 layer : 무엇이 잘못 되었는지 명확하게 전달, 상위 레이어는 전달받은 error를 현재 context에서 판단
    - 최상위 layer (프론트엔드) : 사용자에게 전달되는 메시지 표현 책임
    - retry 정책 : transient 에러만, 상한 명시, 대기시간을 점점 늘림, 그럼에도 실패하면 표준에러로 상위 layer로 전달
      - action tool을 재시도 하면 중복이 생길 수 있음, 여러 레이어가 각자 재시도 하면 회수가 곱해짐
      - 트레이드 오프 : 성공율은 올라가지만, 그만큼 응답이 늦어지게됨
  - Graceful Degradation
    - 시스템의 일부가 실패해도 남은 부분으로 사용자에게 최대한의 가치를 전달하는 설계 패턴
