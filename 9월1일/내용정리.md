# 궁금한점

1. 전통 ML 모델들을 “언제 쓰면 좋은지 + 대표 예시 + 스케일링 + 2026년 현업 사용감

좋아. **지금까지 나온 전통 ML 모델들을 “언제 쓰면 좋은지 + 대표 예시 + 스케일링 + 2026년 현업 사용감” 기준으로 한 번에 정리**해두면 앞으로 모델 고를 때 꽤 편해.

네 분류 실습에서도 Logistic Regression → Decision Tree → Random Forest → XGBoost → LightGBM 순으로 다루고 있어.

| 모델                    | 한번 써보기 좋은 예시                     | 데이터 특징                  | Scaling           | 2026 현업 사용감                            |
| ----------------------- | ----------------------------------------- | ---------------------------- | ----------------- | ------------------------------------------- |
| **Linear Regression**   | 집값, 매출, 수요 예측                     | 관계가 비교적 선형           | 필수 X            | **높음**. 분석/기준모델로 여전히 강함       |
| **Ridge**               | 집값 + Feature가 많고 서로 상관 높음      | 다중공선성 존재              | **권장/중요**     | **높음**. 안정적인 선형 모델                |
| **Lasso**               | 변수 많은 데이터에서 중요한 변수 선별     | 일부 Feature 제거하고 싶음   | **권장/중요**     | **중간~높음**                               |
| **Logistic Regression** | 고객 이탈 여부, 대출 부도, 구매 여부      | 이진/다중 분류               | 보통 **권장**     | **매우 높음**. 빠르고 해석 가능             |
| **Decision Tree**       | 대출 승인 규칙, 생존 조건 찾기            | Rule 설명이 중요             | X                 | **중간**. 단독 최종모델보다 설명용          |
| **Random Forest**       | 불량품 분류, 이탈 예측, 집값              | 일반적인 Tabular             | X                 | **높음**. 강력한 baseline                   |
| **XGBoost**             | 부도/이탈/사기/집값/랭킹                  | 구조화된 Tabular             | X                 | **매우 높음**                               |
| **LightGBM**            | 수십만~수백만 행의 Tabular                | 데이터가 크고 속도 중요      | X                 | **매우 높음**                               |
| **KNN**                 | 비슷한 고객 찾기, 작은 분류 데이터        | 데이터가 작고 거리 의미 있음 | **필수에 가까움** | **낮음~중간**. 대규모에는 불리              |
| **SVM / SVR**           | 작은 데이터의 분류, 고차원 데이터         | 행 수는 적고 Feature 많음    | **매우 중요**     | **중간 이하**. 특정 문제에 여전히 좋음      |
| **K-Means**             | 방금 한 고객 세분화                       | Label 없이 비슷한 집단 탐색  | **매우 중요**     | **높음**. Segmentation 대표 모델            |
| **DBSCAN**              | GPS 위치, 이상 밀집지역, 노이즈 포함 군집 | 군집 모양이 불규칙함         | 보통 중요         | **중간**. 공간/이상치 문제에 좋음           |
| **PCA**                 | Feature 100개 → 2~20개 축소               | 고차원/상관 Feature 많음     | 보통 **중요**     | **높음**. 단, 예측모델이 아니라 전처리/분석 |

여기서 현업적으로 제일 중요한 흐름은 **“딥러닝이 나왔다고 전통 ML이 사라진 게 아니다”**라는 거야. AWS SageMaker의 현재 tabular ML 기능에도 Linear 계열, k-NN, LightGBM, XGBoost 등이 계속 정식 알고리즘으로 제공되고 있고, 특히 XGBoost는 분류·회귀·랭킹 모두 지원되는 대표적인 production 알고리즘이야.

특히 **회사 데이터가 DB/CSV 형태의 일반적인 표 데이터라면 `XGBoost / LightGBM / CatBoost` 계열은 지금도 정말 중요해.** 2025년 제조업 ML 리뷰에서도 XGBoost와 LightGBM 같은 gradient boosting 모델이 예지보전, 불량 분류, 실시간 분석 등에 높은 정확도와 계산 효율성을 보이는 주요 선택지로 정리됐고, 2026년 실제적인 노이즈·결측·라벨 부족 조건을 포함한 benchmark에서도 Logistic Regression과 LightGBM 같은 고전/부스팅 모델들이 강한 정확도-실행시간 trade-off를 보였다.

### 모델을 고르는 감각은 이렇게 잡으면 됨

```text
데이터가 표 형태(Tabular)
        │
        ├─ 결과 설명이 매우 중요
        │      → Linear / Logistic Regression
        │      → Decision Tree
        │
        ├─ 일단 성능 좋은 모델 필요
        │      → Random Forest
        │
        └─ 성능을 제대로 뽑고 싶음
               → XGBoost / LightGBM / CatBoost
```

특히 **Random Forest와 Boosting의 위치 차이**를 기억하면 좋아.

```text
Random Forest
→ 전처리 적음
→ 튜닝 비교적 쉬움
→ 안정적
→ "일단 돌려보는 강력한 baseline"

XGBoost / LightGBM
→ 튜닝 요소 더 많음
→ 잘 튜닝하면 Tabular에서 상당히 강함
→ "성능을 본격적으로 뽑는 모델"
```

그래서 실제 프로젝트에서 처음부터 XGBoost 하나만 믿기보다는:

```text
Logistic Regression
        ↓
Random Forest
        ↓
XGBoost / LightGBM
        ↓
Cross Validation으로 비교
```

하는 식이 굉장히 정상적인 접근이야.

### 회귀에서는

예를 들어 **주택가격 예측**이라면:

```text
Linear Regression
→ 가장 단순한 기준

Ridge / Lasso
→ 선형 관계 + 규제

RandomForestRegressor
→ 비선형 관계

XGBRegressor / LGBMRegressor
→ 성능 본격 비교
```

라고 보면 돼.

그리고 평가:

```text
MAE
RMSE
MAPE
R²
```

로 비교.

### 분류에서는

**고객 이탈 예측** 하나만 가지고도 거의 모든 모델을 비교해볼 수 있어.

```text
Logistic Regression
→ 이탈 확률 73%

Decision Tree
→ 어떤 조건 때문에 이탈하는지 Rule

Random Forest
→ 여러 Tree로 안정화

XGBoost / LightGBM
→ 이전 오차를 계속 보정하며 성능 향상
```

평가는:

```text
Accuracy
Precision
Recall
F1
ROC-AUC
```

를 보고.

특히 실제 회사에서는 **Accuracy만 보는 경우보다 목적에 따라 Precision/Recall을 고르는 게 더 중요**할 수 있어.

예를 들어 사기탐지에서는:

```text
사기 100건
정상 99,900건
```

이면 전부 정상이라고 예측해도 정확도 99.9%잖아. 그래서 Recall, Precision, PR-AUC 같은 걸 보게 돼.

### 비지도학습에서는

지금 한 고객 Segmentation이 K-Means의 정석 예시야.

```text
Age
Income
Spending Score
       ↓
StandardScaler
       ↓
K-Means
       ↓
고객 군집
       ↓
VIP / 잠재고객 / 적극소비층 ...
```

K-Means는 지금도 고객 segmentation 같은 분야에서 실제 적용 사례가 계속 나오고 있어. 2025년 국내 실제 캠핑 예약 플랫폼 고객 데이터 연구에서도 RFM과 K-Means를 사용해 고객 세분화의 실무 적용 가능성을 분석했다.

DBSCAN은 조금 다른 상황.

```text
K-Means
●●●     ●●●     ●●●
동그란 덩어리 느낌
K를 미리 정해야 함

DBSCAN
●●
 ●●●●           × ← noise
   ●
불규칙한 모양도 탐색 가능
K를 미리 정하지 않아도 됨
```

그래서 GPS 이동 데이터, 위치 hotspot, 이상치가 섞인 공간 데이터 등에 잘 맞아.

### PCA는 특히 구분해야 함

PCA는:

> **예측 모델이나 군집 모델이 아니라 Feature를 새로운 축으로 압축하는 차원축소 기법**

이야.

```text
Age
Income
Spending
Visit Count
Purchase Count
...
100 Features
       ↓
      PCA
       ↓
10 Components
```

이런 용도.

그리고 우리가 방금 했던 것처럼:

```text
실제 K-Means
→ 원래 20차원 Feature에서 수행

시각화
→ PCA1, PCA2로 내려서 그림
```

처럼 많이 써.

그리고 **2026년 현재 현업 중요도만 아주 거칠게 순위를 매긴다면**, 일반적인 구조화 데이터 기준으로는 이런 감각이면 돼.

```text
★★★★★  XGBoost / LightGBM / CatBoost
★★★★★  Logistic Regression
★★★★☆  Random Forest
★★★★☆  Linear / Ridge / Lasso
★★★★☆  K-Means (Segmentation이 필요할 때)
★★★★☆  PCA (전처리/분석)

★★★☆☆  Decision Tree 단독
★★★☆☆  DBSCAN
★★★☆☆  SVM

★★☆☆☆  KNN
```

이건 **성능 순위가 아니라 “현업에서 마주칠 가능성 + 쓸모”를 합친 정성적인 감각**이야. 특정 문제에서는 SVM이나 KNN이 XGBoost보다 당연히 더 좋을 수도 있어.

그리고 하나 추가해서 기억해두면 좋은 게 **CatBoost**야. 네 실습에는 아직 안 나왔지만 XGBoost·LightGBM과 같은 급으로 자주 비교되고, 특히 `지역`, `직업`, `상품종류`, `회사명`처럼 **범주형 Feature가 많은 Tabular 데이터**에서 매우 편리한 선택지야. 현재 SageMaker도 CatBoost, LightGBM, XGBoost를 모두 tabular 알고리즘 선택지로 제공하고 있다.

결국 실무 관점에서는 모델 이름을 전부 외우기보다 **이 판단 순서가 더 중요해.**

> **① Label 있나? → 지도/비지도**
> **② Target이 숫자인가 범주인가? → 회귀/분류**
> **③ Tabular인가 이미지·텍스트인가?**
> **④ 설명력이 중요한가 성능이 중요한가?**
> **⑤ 데이터 크기·Feature 수·범주형 비율은?**
> **⑥ Baseline 여러 개 돌려보고 CV로 실제 성능 비교**

이 사고방식이 있으면 처음 보는 데이터가 와도 “아 이거 LightGBM부터 비교해보자”, “이건 K-Means보다는 DBSCAN이 맞겠다”, “이건 Logistic을 baseline으로 깔자”가 자연스럽게 나와.

2. 전통 머신러닝을 딥러닝으로 대체되고 있는 부분이 있나?

있어. 다만 **“전통 ML이 전반적으로 딥러닝에 대체되는 중”이라고 보면 틀리고**, 데이터 유형에 따라 완전히 달라.

지금 네가 본 모델들 기준으로 보면 대략 이렇게 정리할 수 있어.

| 전통 기법                     | 딥러닝 대체/보완 흐름                | 현재 감각                                    |
| ----------------------------- | ------------------------------------ | -------------------------------------------- |
| Linear / Logistic Regression  | MLP, TabTransformer, TabPFN 등       | **대체 아님**. 여전히 baseline/설명용 강함   |
| Decision Tree                 | DNN/Transformer                      | 단독 Tree는 최종모델 비중 낮지만 설명용 유지 |
| Random Forest                 | Tabular DL                           | 일부 경쟁하지만 **여전히 많이 사용**         |
| XGBoost / LightGBM / CatBoost | Tabular Transformer, TabPFN, TabR 등 | **아직 대체됐다고 보기 어려움**              |
| KNN                           | 임베딩 + Neural Retrieval            | 많이 대체되는 편                             |
| SVM                           | DNN                                  | 이미지/텍스트에서는 상당 부분 대체           |
| PCA                           | Autoencoder                          | 복잡한 비선형 데이터에서는 대체/보완 증가    |
| K-Means                       | Deep Embedded Clustering 등          | 고차원·이미지·텍스트에선 DL과 결합 증가      |
| DBSCAN                        | Deep clustering / learned embeddings | 특수 목적에선 여전히 유효                    |

가장 중요한 건 **Tabular 데이터**야.

### 1. XGBoost/LightGBM 같은 건 아직 딥러닝이 못 밀어냈음

회사 DB처럼:

```text
고객ID
나이
소득
구매횟수
직업
지역
최근접속일
...
```

같은 구조화된 표 데이터에서는 2026년에도 XGBoost, LightGBM, CatBoost 같은 GBDT가 아주 강해. 최신 연구에서도 구조화된 데이터에서는 tree 기반 모델이 여전히 널리 쓰인다고 명시하고 있고, neural net과 GBDT 중 어느 쪽이 무조건 우월하다고 보기 어렵다는 대규모 benchmark 결과도 있어. ([Nature][1])

그래서:

```text
Tabular
→ XGBoost / LightGBM / CatBoost
```

이 조합은 아직 현역 중의 현역이라고 보면 돼.

최근에는:

```text
TabPFN
TabTransformer
FT-Transformer
TabR
```

같은 **Tabular 전용 딥러닝/파운데이션 모델**이 빠르게 발전하고는 있어. 실제로 TabR 같은 모델은 일부 benchmark에서 GBDT를 넘는 결과도 보고됐어. ([arXiv][2])

하지만 아직은:

> **“XGBoost 시대 끝, 이제 Transformer”**

이 수준은 전혀 아님.

---

### 2. 반대로 이미지·텍스트·음성에서는 전통 ML이 많이 밀림

여기서는 딥러닝이 훨씬 강하게 대체했어.

예를 들어 이미지 분류를 예전에는:

```text
이미지
↓
SIFT / HOG 같은 사람이 만든 Feature
↓
SVM
```

이렇게 했다면 지금은:

```text
이미지
↓
CNN / ViT
↓
분류
```

가 기본이지.

텍스트도 과거에는:

```text
TF-IDF
↓
SVM / Logistic Regression
```

이 많았다면,

지금은:

```text
Transformer / LLM Embedding
↓
분류
```

가 많아졌고.

즉:

> **Raw 이미지·텍스트·음성처럼 Feature 자체를 사람이 만들기 어려운 데이터일수록 딥러닝이 기존 ML을 많이 대체했다.**

---

### 3. PCA → Autoencoder도 실제 변화가 있음

이건 네가 방금 배운 PCA와 연결하면 좋아.

PCA:

```text
100차원
↓
선형 조합
↓
10차원
```

Autoencoder:

```text
100차원
↓
Neural Network
↓
10차원 latent vector
```

PCA는 **선형 관계만 압축**하지만 Autoencoder는 복잡한 비선형 관계도 학습할 수 있어.

그래서 이미지, 센서, 고차원 고객 행동처럼 데이터 구조가 복잡하면:

```text
PCA
→ Autoencoder
```

로 가는 경우가 있어.

실제로 최근 고객 segmentation 연구에서도 Autoencoder로 고차원 특징을 압축한 뒤 K-Means를 적용하는 hybrid 방식이 계속 연구되고 있어. ([AIS eLibrary][3])

그렇다고 PCA가 없어지는 건 아니야.

```text
PCA
→ 빠름
→ 학습 거의 없음
→ 설명하기 쉬움

Autoencoder
→ 복잡한 패턴 학습
→ 데이터 많이 필요
→ 학습 비용 큼
```

이라 용도가 달라.

---

### 4. K-Means도 “대체”보다는 딥러닝과 결합되는 방향

예를 들어 예전:

```text
원본 Feature
↓
Scaling
↓
K-Means
```

최근 고차원 데이터에서는:

```text
이미지 / 텍스트 / 고객행동
↓
Autoencoder / Transformer
↓
Embedding
↓
K-Means
```

이런 식이 많아.

즉 K-Means 자체를 버리는 게 아니라:

> **좋은 거리 공간을 딥러닝이 만들어주고, 마지막 군집은 K-Means가 하는 구조**

가 많아지는 거야. 최근 deep clustering 연구도 이런 방향을 많이 사용해. ([ScienceDirect][4])

이건 꽤 중요한 포인트야.

---

### 5. KNN은 딥러닝/Embedding으로 많이 바뀜

예전:

```text
원본 Feature
↓
Euclidean Distance
↓
KNN
```

지금 텍스트/이미지 검색은:

```text
Deep Learning Model
↓
Embedding Vector
↓
Cosine Similarity / ANN Search
```

방식이 많이 쓰여.

예를 들어 LLM RAG도 사실 큰 틀에서:

```text
문서
↓
Embedding Model
↓
Vector DB
↓
가까운 문서 검색
```

이니까 **KNN 철학은 살아 있는데 Feature를 딥러닝이 만들어주는 것**에 가까워.

---

### 6. SVM은 가장 많이 위치가 바뀐 모델 중 하나

2000~2010년대에는:

```text
이미지 → SVM
텍스트 → SVM
음성 → SVM
```

이 엄청 강했어.

지금은 이 영역들이 거의:

```text
CNN
Transformer
LLM
```

로 넘어갔지.

그래도:

```text
데이터 수 적음
Feature 수 많음
명확한 margin이 있음
```

같은 작은 데이터 문제에서는 아직 SVM이 꽤 괜찮아.

---

결국 시대 흐름은 이렇게 보면 정확해.

```text
과거

사람이 Feature 설계
↓
PCA
↓
SVM / KNN / Logistic / K-Means
```

에서

```text
현재

Deep Learning이 Representation 학습
↓
Embedding / Latent Feature
↓
분류 / 회귀 / 검색 / 군집
```

으로 많이 이동했어.

하지만 **Tabular 데이터는 예외적으로 전통 ML이 여전히 강하다**는 게 핵심이야.

그래서 2026년 기준으로 아주 거칠게 말하면:

> **이미지·텍스트·음성 → 딥러닝이 사실상 주류**
> **정형 Tabular → XGBoost/LightGBM/CatBoost가 여전히 매우 강함**
> **고차원 군집/차원축소 → PCA/K-Means를 딥러닝이 완전히 없애기보다 Autoencoder/Embedding과 결합하는 방향**

이렇게 잡으면 현재 ML 생태계를 꽤 정확하게 보는 거야.

3. 옵티마이저가 잘 동작하더라도 결국 이게 글로벌 미니멈인지 확신 못하지 않나?

옵티마이저는 global minimum을 찾았는지 알 수 없고, gradient가 더 이상 크게 감소하지 않는 좋은 지점을 찾을 뿐이다. 신경망 파라미터가 수백만~수십억 개처럼 엄청 많아지면, 좋은 해가 하나만 있는 게 아니라 비슷하게 낮은 loss를 갖는 해가 많이 존재하는 경우가 많다. 따라서 딥러닝에서는 global minimum 자체보다 validation/test 성능이 더 중요하다.

그리고 이게 바로 왜 SGD의 노이즈가 오히려 도움이 될 수 있는지랑도 연결. 작은 local minimum이나 saddle point에서 빠져나오는 데 도움이 됨.
